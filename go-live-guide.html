Go live, step by step

Everything from unzipping the project to a working, private, daily-syncing dashboard — written for someone who has never deployed a website before.

00

Before you start

Install Node.js — the one piece of software everything below runs through
  1. Go to nodejs.org and click the green "Download Node.js (LTS)" button.
  2. Open the installer, click Next/Continue through it, keeping every default.
What's "a terminal"? A plain text window for typing commands instead of clicking buttons — you'll need it for a handful of short copy-paste steps below.
Mac: Cmd + Space, type Terminal, Enter.   Windows: Start key, type PowerShell, Enter.
terminal
$ node -v
v22.11.0  ← seeing a version number like this means you're ready
01

Where you create an account

Just one — Vercel

Go to vercel.com/signup and sign up. "Continue with Email" or "Continue with GitHub" both work — pick whichever is easier. You do not need a GitHub account for anything else in this guide.

Expect
Your empty Vercel dashboard — an "Overview" page with no projects on it yet.
02

What you upload/import

There's no upload button — just unzip

Unzip kvmechelen-scouting-hub.zip somewhere easy to find, like your Desktop. You get a folder named scouting-dashboard — that's the entire project. You won't open, edit, or individually upload anything inside it; one command in Step 3 sends the whole folder to Vercel at once.

Expect
A scouting-dashboard folder containing src, public, docs, scripts, package.json, vercel.json.
03

Connect the project to Vercel

The one part that uses the terminal — every line is copy-paste

Open your terminal and run these one at a time, waiting for each to finish.

terminal
$ npm install -g vercel
…installs with no red error text (yellow warnings are fine)
terminal
$ vercel login
…enter your email, click the confirmation link Vercel emails you
Success!

Move into the folder you unzipped (adjust the path to match where you put it):

terminal
$ cd Desktop/scouting-dashboard
$ npm install
…a progress bar, then finishes clean (1–2 minutes)
terminal
$ vercel
Set up and deploy? y
Which scope? (press Enter)
Link to existing project? n
Project's name? (press Enter, or type kvmechelen-scouting-hub)
Directory? (press Enter for ./)
✅  Preview: https://scouting-dashboard-xxxx.vercel.app
This first URL won't work correctly yet — there's no database or API keys attached. Expected at this stage; Steps 4–5 fix it.
Expect
Your project now listed on vercel.com/dashboard — this is the page you'll return to for the rest of the steps.
04

Create/connect the PostgreSQL database

One command — Neon provisions and connects automatically

Still inside the scouting-dashboard folder in your terminal:

terminal
$ vercel install neon
Choose a plan: Free (press Enter)
…may open a browser tab — click Authorize
Database created and connected.

This adds an environment variable named DATABASE_URL to your project automatically — exactly what the app looks for. Nothing else to do here.

Click
Project → Storage tab
Expect
A database listed there, provided by Neon.

About mock: SofaScore has no public API to connect to, so match ratings shown everywhere are realistic demo data, not live numbers — a limitation of the data source itself, not something this deployment can change.

To generate CRON_SECRET — a password only your app and Vercel's scheduler need to know:

mac / linux
$ openssl rand -hex 32
windows powershell
$ -join ((48..57)+(65..90)+(97..122)|Get-Random -Count 32|%{[char]$_})

Copy what it prints and paste it as the CRON_SECRET value.

Expect
Seven rows total on the Environment Variables page: DATABASE_URL + the six above.
06

Where the SCOUTASTIC API token goes

Exactly one place — never in the zip, never in code

Only the SCOUTASTIC_API_TOKEN environment variable from Step 5. It's read exclusively on Vercel's servers — checked directly during development that it never reaches a browser.

  • No token yet? The app runs fine without one — it falls back to a realistic ~400-player demo dataset so every page still works.
  • Add the real token whenever you get it, then redeploy (vercel --prod, Step 10).
07

The daily 06:00 synchronization

Nothing to configure — it's already built in

vercel.json already defines the schedule; Vercel reads it the moment you deploy.

Click
Project → Settings → Cron Jobs
Expect
Three entries — two for /api/cron/scoutastic-sync, one for /api/cron/weekly-update.
Two entries for the same sync is intentional, not a bug: "06:00 in Belgium" falls on two different UTC times across the year (daylight saving), so the app pings itself at both and quietly skips the one that isn't actually 06:00 locally.
08

Confirm the database is persistent

A 60-second check, once your site is live
  1. Open your live URL → Shortlists → + Create Shortlist → name it "Test" → save.
  2. Close the tab entirely (or open a different browser).
  3. Go back to Shortlists.
Expect
Your "Test" shortlist is still there — confirming data lives in the real Neon Postgres database, not somewhere temporary.

Feel free to delete the "Test" shortlist afterward.

09

Keep the dashboard/API private

optional free, already built in — no $150/mo add-on needed

By default, anyone with the URL can open the app. Vercel's own way to password-protect a production URL costs $150/month (a Pro-plan add-on) — not worth it here. This project ships its own free alternative instead.

You already added these two in Step 5:

Vars
BASIC_AUTH_USER and BASIC_AUTH_PASSWORD
Expect
Opening the live URL in an incognito window shows a native "Sign in" popup before anything loads.

Leave both blank instead if you'd rather keep the site open for now — everything else in this guide works exactly the same either way.

10

Get the final HTTPS URL

One command — this is the real, production deploy
terminal
$ vercel --prod
✅  Production: https://kvmechelen-scouting-hub.vercel.app [copied to clipboard]

That URL is your live dashboard — also always visible at the top of your project page, and under Settings → Domains (where a custom domain like scouting.kvmechelen.be can be attached later, entirely optional).

One last step — load the starting data

The database is empty until seeded once. Get the value to paste from Settings → Environment Variables → DATABASE_URL → reveal → copy (starts with postgres://).

mac / linux
$ DATABASE_URL="paste-here" npm run db:seed
…Seed complete.  (~15–20 seconds)
windows powershell
$ $env:DATABASE_URL="paste-here"; npm run db:seed
Expect
Refreshing your live URL now shows real data on every page instead of an empty dashboard.
